# 公開リポジトリを点検した実例

2026-10-03に、この公開DBのコミット `ffed2e9c0529832db9a6438c36c3c7baa43c7d88` を読み取りで点検しました。対象はソース、配布JSON、公開されたCIの定義です。個人端末、GitHubアカウントの設定、ホスティングの設定は確認していません。外部AIのAPIは呼び出していません。

2026年10月3日の点検には14ルールを使い、[当時の結果JSON](https://github.com/sakimyto/security-knowledge/blob/e26c207650d4eff81214224684eadd02ccb89218/examples/public-repository-review.json)へ確認範囲と根拠を残しました。CIの外部Actionが変更可能な `v6` タグを参照していたため、SEC-007で修正候補を記録しました。v0.4.1では、公式リポジトリで確認したコミットSHAに参照を固定しました。公開設定の権限や実行時の境界は、ソースの修正だけでは確認できません。

2026年10月9日の更新では、現行の16ルールとカタログのハッシュに合わせて[ソースのみの確認結果](../examples/public-repository-review.json)を更新しました。必要な実環境の証拠がないため、全項目をunverifiedで記録しています。CIの参照固定を確認しただけで、ルール全体の適合とは判定しません。

10月3日時点では、残る13ルールを `unverified` としました。依存パッケージのないCLIでも、Node.jsの稼働版や最新アドバイザリの照合が必要です。公開ファイルの検査だけで、Git履歴を含む秘密の混入、MFA、セッション失効、認可、監査ログ、バックアップを合格にはできません。

配布データの参照整合性と全テストを検証します。この結果はDBとツールの動作確認であり、環境全体の安全性を証明するものではありません。`report.mjs` も、報告の形式、ハッシュ、全ルールの記録を検証するツールです。証拠の真偽は別に確認します。

同じ手順を使う場合は、環境のコミットや設定の版を固定し、実際に取得した証拠を記録してください。確認できない項目を残すことで、次回点検に必要な権限や試験を特定できます。
