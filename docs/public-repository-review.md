# 公開リポジトリを点検した実例

2026-10-03に、この公開DBのコミット `ffed2e9c0529832db9a6438c36c3c7baa43c7d88` を読み取りで点検しました。対象はソース、配布JSON、公開されたCIの定義です。個人端末、GitHubアカウントの設定、ホスティングの設定は確認していません。外部AIのAPIは呼び出していません。

点検には14ルールを使い、[結果JSON](../examples/public-repository-review.json)へ確認範囲と根拠を残しました。CIの外部Actionが変更可能な `v6` タグを参照していたため、SEC-007で修正候補を記録しました。v0.4.1では、公式リポジトリで確認したコミットSHAに参照を固定しました。公開設定の権限や実行時の境界は、ソースの修正だけでは確認できません。

残る13ルールは `unverified` としました。依存パッケージのないCLIでも、Node.jsの稼働版や最新アドバイザリの照合が必要です。公開ファイルの検査だけで、Git履歴を含む秘密の混入、MFA、セッション失効、認可、監査ログ、バックアップを合格にはできません。

配布データの参照整合性と17件のテストは成功しました。この結果はDBとツールの動作確認であり、環境全体の安全性を証明するものではありません。`report.mjs` も、報告の形式、ハッシュ、全ルールの記録を検証するツールです。証拠の真偽は別に確認します。

同じ手順を使う場合は、環境のコミットや設定の版を固定し、実際に取得した証拠を記録してください。確認できない項目を残すことで、次回点検に必要な権限や試験を特定できます。
